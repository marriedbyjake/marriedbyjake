# Editing Married by Jake

Your website is live at [marriedbyjake.com](https://marriedbyjake.com). Edit it in [EmDash](https://marriedbyjake.com/_emdash/admin) using your own passkey. Save a draft, preview it, then Publish. The publishing banner confirms when the new website is live.

## First ten minutes together

1. **Sign in on Jake’s device.** Use Jake’s existing account and passkey. His account is active and has a registered passkey; signing in on his own device is the final access check.
2. **Tour the public website.** Open the homepage, a service, [prices](https://marriedbyjake.com/serviceandprice), a review with photographs and [contact](https://marriedbyjake.com/contact). Check the phone layout too.
3. **Open one real change.** In Website sections, find **Home · Main introduction**, or choose another section Jake actually wants to update. Expand its existing settings block. Keep the entry and slug.
4. **Save draft and preview.** The public page keeps the published version. Preview shows the saved draft. Preview links are private links valid for one hour; anyone with the exact link can view that entry, so keep them private.
5. **Publish when ready.** Watch the banner or [publishing status](https://marriedbyjake.com/_publishing). A build can take several minutes. Wait for confirmation, then open the public page in a fresh tab. The previous healthy website stays available if a release fails.

Use a genuine approved edit for this demonstration. There is no need to create a disposable public post or overwrite a review to test the system.

## Where to edit

| You want to change… | Open in EmDash |
| --- | --- |
| Homepage or city introduction | Website sections → the named page’s **Main introduction** |
| Biography and About video | Website sections → **About Jake** entries |
| FAQs | Website sections → **FAQs · Questions and answers** |
| Ceremony and MC prices | **Pricing** → the existing entry |
| Pricing explanation and inclusions | Website sections → **Service and price · Page copy and inclusions** |
| Service description | **Services** → the existing service |
| A couple’s review, venue, pictures or map position | **Wedding testimonials** → that review |
| Blog, readings or information pages | Their original content collections |
| Shared values, statistics, steps or enquiry invitation | Website sections → the named **Shared** entry |
| Page photos or background video/poster | Website sections → **Shared · Page photographs** or **Shared · Background videos and posters** |
| Footer email, phone and legal notice | Website sections → **Shared · Footer and legal notice** |
| Navigation, social profiles and featured links | **Menus** |
| Website title, tagline, logo or favicon | **Settings → General** |
| Page search title, description or social image | That content entry’s search fields; static pages use Website sections → **Search · /page** |

There are 47 named Website sections and six connected menus. The private [editing guide](https://marriedbyjake.com/_publishing#editing) lists every section and its public page.

## Everyday editing

**Photos:** upload through Media, add useful alt text, then select the image in the entry. For a background video, update its matching poster at the same time. Publishing includes the referenced originals in the website release.

**Reviews:** preserve the couple’s words and attribution. Venue and location fields control review associations; latitude and longitude control the overview map position. The existing 31 private draft reviews remain private. Complete and review an entry before publishing it.

**Prices:** the Australian ceremony fee is **$2,000 plus GST plus travel**. Edit the Pricing entry and **Service and price · Page copy and inclusions**. Share [the pricing page](https://marriedbyjake.com/serviceandprice) directly when appropriate. It is excluded from menus, site search, the sitemap and search-engine indexing. Keep pricing copy and links off other public pages. The old `/celebrantcost` URL forwards to this page; its original content remains in EmDash.

**Menus and general settings:** these save directly and queue a release without a draft step. Review those changes before saving. Ordinary content and Website sections have the draft → preview → publish workflow.

**Search fields:** blank values keep the existing defaults. Changing a slug changes a public URL, so arrange a redirect before doing that. Keep the named Website sections published; removing a required section stops the next release to protect the healthy site.
